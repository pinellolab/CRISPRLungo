50 bp deletion replaced by an 80 bp insert carrying 35 substitutions
====================================================================
Simulated 2026-11-11.  Amplicon 426 bp, cut after 80.  The 80 bp insert is the
80 bp that would sit at the cut with 35 of its bases changed, so it is 56 %
identical to the sequence it replaces.  Edited allele 456 bp (net +30 bp).
Reads at ~96 % identity (1.5 % sub, 1.0 % ins, 1.5 % del), both strands.
Treated 4,000 reads: 2,400 unedited, 1,200 replaced, 250 with the 50 bp
deletion alone, 150 with a plain 8 bp deletion.  Control 3,000 unedited.

Detection (default settings)
----------------------------
  Replaced   1,200 reads -> Ins 963, Complex 237      (0 called WT)
  Unedited   2,400 reads -> WT 1,952, Sub 344, Ins 55, Del 49
  Del_only     250 reads -> Del 233, LargeDel 17  (81_130:Del_50 in 216)
  Indel_8      150 reads -> Del 132, WT 13
Every replaced read is called edited.  Detection is not the problem.

How the edit is described
-------------------------
minimap2 aligns the replacement THROUGH the sequence it replaces (56 % identity
is enough to chain), so the event is reported as ~12 substitutions plus 7 small
insertions - 19 induced patterns - rather than as one 50 bp deletion plus one
80 bp insertion.  Because the inserted bases are part of the mutation key and
each read carries its own sequencing errors in them, the 1,200 replaced reads
produce 957 distinct patterns; the largest holds 31 reads (2.6 %) and the top
ten together hold 121.  The allele table and plot therefore scatter one allele
across hundreds of rows.

Calling the intended edit  (--induced_sequence_path induced.fasta)
------------------------------------------------------------------
  --induced_paritial_similiarity   replaced reads called as carrying the edit
            0.8 (default)            416 / 1,200   34.7 %
            0.6                      955 / 1,200   79.6 %
            0.5                    1,039 / 1,200   86.6 %
            0.4                    1,097 / 1,200   91.4 %
            0.3                    1,113 / 1,200   92.8 %
False positives at every threshold tested: 0 of 2,400 unedited, 0 of 250
deletion-only and 0 of 150 indel reads.  "Precise" stays at 22 whatever the
threshold, because it demands all 19 induced patterns and nothing else, which an
ONT read almost never satisfies.

Things that do not help
-----------------------
  --minimap2_opt "-B9 -O14,40"   gives a clean 84_131:LargeIns_77 for the reads
      that survive, but minimap2 then soft-clips instead of opening the gap and
      891 of 4,000 reads are dropped as short (344 of 1,200 replaced remain).
  --range_both_end_region 150    keeps the reads but they come back as WT,
      because the clipped part carries no mutation.
  edited allele as the reference, with the unedited sample as the control:
      the wild-type difference is in the control too, so it is filtered as
      background and the unedited reads come back as WT.
  the same inverted run without a control: sequencing errors are no longer
      filtered and everything becomes Complex.
  --background_max_len (added here) does not rescue the inverted run either:
      there is no long mutation to protect, because the aligner never opened a
      gap in the first place.

Recommendation
--------------
Run in the normal orientation with --induced_sequence_path and
--induced_paritial_similiarity 0.4-0.5, and read the result from
Precise + Precise_with_mutations + Partial + Partial_with_mutations rather than
from Precise alone.  Expect the allele plot to show the replacement spread over
many rows; the per-read table is the reliable readout for this edit.
